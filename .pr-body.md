Extends the system.status JSON-RPC method to expose three additional fields for the frontend health indicator:

- maxAgents (usize → JSON number): Agent manager capacity from the concurrent agent registry cap
- version (string): intentd package version (CARGO_PKG_VERSION)
- uptimeSeconds (u64 → JSON number): Daemon uptime since DaemonControl::start_time

## Wire Format
All fields use camelCase on the wire per existing protocol conventions:
- maxAgents
- version
- uptimeSeconds

## Implementation
- Added control: Option<Arc<dyn SystemControl>> field to WsInner struct
- Updated all WsApiServer constructors (new, new_insecure, new_with_reverse, new_insecure_with_reverse) to accept the control parameter
- Modified WSS connection_loop to pass self.control.as_ref() to conn::process_frame
- Updated daemon composition in main.rs to pass control to boot-time WSS servers
- Runtime-toggled WSS listeners currently pass None (documented limitation; to be addressed in follow-up)

## Testing
- Added WSS e2e test wss_system_status_includes_capacity_version_uptime in e2e_wss_runtime_control.rs
- Verifies all three new fields are present and correct over a real WebSocket connection
- Existing UDS test coverage remains green

## Rust Documentation
All three fields are documented in the SystemStatus struct definition in intent-transport/src/control.rs:
- max_agents: Agent manager capacity (concurrent agent limit)
- version: intentd package version string
- uptime_seconds: Daemon uptime in seconds since start
